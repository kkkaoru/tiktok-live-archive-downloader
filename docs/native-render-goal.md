# ゴール: Mac アプリを組み合わせた全編編集と配信用描画

FFmpeg と同じ方式の再現は目的にしない。目的は、人間が Final Cut Pro で後から微調整できる
全編タイムラインを自動で作り、その最終状態から品質を検証済みの配信ファイルを自動で作ること。
Final Cut Pro に依存する理由は、人間による後からの微調整だけである。

## 解決する問題

| # | 問題 | 現状 |
|---|---|---|
| P1 | ネイティブ描画のファイルが FFmpeg より約 26% 大きい | AVFoundation の型付き設定では maxrate/bufsize を指定できない |
| P2 | FCPXML がパートごとに分かれ、全編を FCP で直せない | 1 配信 508 パートなら 508 イベントになる |
| P3 | FCP 上でぼかしは編集できず、字幕の外側の黒縁も再現されない | ぼかしはマーカー、字幕は Basic Title による近似 |
| P4 | FCP で直した内容が配信ファイルに反映されない | 配信ファイルは計画から直接描画している |
| P5 | `styledCaptions` で作った出力は `edit_completion` を通らない | 完了判定は ASS の SHA-256 か、従来のネイティブ字幕だけを認める |
| P6 | 計画から描画リクエストを作る変換がスクラッチにしかない | 解決: `replay.native_render`（パートごとの `media_edit` と `media_edit_batch`）と `replay.native_join`（無劣化連結）を追加 |
| P7 | 可変フレームレートの素材で、ネイティブは FFmpeg と 1 フレームずれる | 正しさの基準を FFmpeg に置いていた |
| P8 | パイプライン全体の所要時間が短くなっていない | 9/29 の配信の描画は約 19 分、ネイティブ化で約 1 割短縮 |
| P9 | FCP プロジェクトの字幕が白い塊・黒い塊になり読めない | Basic Title の縁取りは文字の上に描かれ、`strokeWidth` 6 が塗りを覆う。`fontSize` 56 は配信用の約 2 倍。ぼかしも入っていない |

## 目標の構成

1. **正本は 1 本の全編 FCPXML とする**（1 配信 = 1 イベント = 1 プロジェクト）。
   - `python -m replay.fcp_project` が描画計画と各パートの ASS から生成する。
   - 素材の切り出し、ぼかし、字幕、音声を、すべて FCP 上で編集できる部品として持つ。
2. **FCP / Motion の編集可能な部品で、配信と同じ見た目を再現する。再設計は未完了。**
   - 字幕の表示段階ごとに 3 枚の Basic Title を重ねる旧方式は、下記の規模試験で失敗したため再使用しない。
   - 字幕はセンテンス単位の Motion タイトルとし、認識順・認識時刻に沿って文字が現れるアニメーションを機械生成する。
     旧方式のデータ構造、ASS の表示段階、瞬時の切替フレームを踏襲する必要はない。
     字幕の欠落・順序逆転・音声とのずれは防ぎつつ、Motion に適した定義へ再設計する。
   - 表示の滑らかさを優先する。瞬時の文字追加は診断用とし、納品ではフェード・補間曲線を使って
     自然に現れる動きを実描画で検証する。アニメーション定義は可能な限り共有コードで生成し、
     GUI による語ごとの手作業は行わない。これは配色・二重縁・編集可能性や他の品質条件の緩和ではない。
   - データ構造の最適化とアプリ側の読込負担を常に設計基準にする。原則 1 センテンス = 1 タイトルとし、
     テンプレート・効果定義は共有する。単語・表示段階・フレームごとのタイトル複製や同一内容の冗長なキーは作らない。
     本文・認識時刻・必要な差分だけを保持し、滑らかさは Motion の補間で表現する。
     小規模段階で要素数・読込時間・メモリ・編集応答を実測し、単なるファイル縮小や compound 化で軽量化を認定しない。
     Apple は Outline の Layer Order と Sequence Text の Custom Speed を公開しているが、
     その仕様だけでは独自テンプレートや FCPXML の実描画を保証しない。
   - ぼかしは元クリップへの矩形マスク付き Gaussian を候補とする。合成試験では位置変更と
     キーフレーム後の移動を確認済み。全編のマスク範囲・強さ・時間の検証は未完了。
   - 2 テキストオブジェクト入りタイトルの初期試験は白潰れで不合格だった。
     負の `strokeWidth` を機械生成した合成試験では、塗りと白黒の二重縁を実出力で確認した。
     ただしグラデーション・陰影位置・実出力のコントラストは未合格であり、
     DTD 適合・取り込み・全デコードだけで字幕の視認性を合格扱いしない。
   - 追試では FCPXML の文字スタイル上書きを外し、テンプレート側に字体・グラデーション・
     白黒の縁を持たせると、青い塗りと上下の色変化が実出力に現れた。
     新設タイトルは FCP のタイトル一覧で認識を確認してから取り込む。
     `replay.motion_caption` は、ローカルの既知バージョンの Apple テンプレートから
     2 テキストオブジェクトの候補を生成する共有処理である。Apple の素材は同梱せず、
     元ファイルを変更しない。生成候補の実描画、行間・語時刻、FCPXML 生成器への接続、
     ネイティブ描画との一致、全編への適用は未完了。色設定値だけで 7:1 を認定しない。
3. **自動処理の配信は、計画からネイティブで 1 パス描画する。**
   - 現行の `python -m replay.native_render` は局所補修済み素材の切り出しと字幕から描画リクエストを作り、
     最大 32 件ずつの `media_edit_batch` にまとめる。新経路は同じセンテンスと認識時刻を基にした Motion 定義を
     FCPXML と配信用描画で共有する。ASS の表示段階は移行元であり、アニメーションの正本にはしない。
   - `python -m replay.native_join` が、各パートのパケット数・コーデック・時間軸を計画と照合してから、
     再エンコードせずに連結し、連結後のフレーム数を再確認する。
   - 人間が FCP で手を入れた後は、FCP の「共有」または「Compressor へ送信」で、同じ Compressor
     プリセットを使って書き出す。人間はその時点で FCP にいるので、自動化の妨げにならない。
   - FCPXML を読むネイティブ描画を作る場合は、理解できない要素があれば理由を示して止まる。
     編集を黙って落とさない。
4. **エンコードは経路ごとに、実測で決めた方式を使う。**
   - 自動処理: ネイティブ 1 パス描画のハードウェア HEVC（平均 4.5 Mbps）で、そのまま最終ファイルにする。
     再エンコードの世代が増えないので、同じサイズなら Compressor で再エンコードするより画質が高い。
   - 人間が FCP で手を入れた後: FCP の「共有」で、Compressor のプリセット（`.compressorsetting`）を使う。
     プリセットのビットレートは `auto-bit-rate-purpose` を 10 にしないと `data-rate` が効かない。

   | 方式（同じ 1 パート。VMAF は 40 Mbps の中間ファイルを基準とした値） | サイズ | VMAF |
   |---|---|---|
   | ネイティブ 1 パス HEVC 4.5 Mbps | 6.03 MB | 95.2 |
   | ネイティブ 1 パス HEVC 3.5 Mbps | 4.70 MB | 94.1 |
   | Compressor（2 世代目）HEVC 3.5 Mbps、上限 150% | 6.85 MB | 94.6 |
   | FFmpeg 方式（現状） | 6.35 MB | — |

5. **完了判定を新しい経路に対応させる。**
   - `edit_completion` が、正本の FCPXML の SHA-256、描画リクエスト、Compressor のジョブ、
     出力の検証結果を確かめて完了とする。

## 旧方式の較正値（1080×1920、Final Cut Pro Creator Studio で実測）

以下は比較用の旧方式の記録であり、新しいテンプレート方式の検証結果ではない。

| 要素 | 規則 | 実測の一致度 |
|---|---|---|
| 文字の大きさ | `fontSize` = libass の em（ASS サイズ × UPM ÷ (winAscent + winDescent)）× 1080 ÷ 高さ。ASS 66 → 27.8716 | 塗りの範囲が libass 相当のネイティブ描画と完全一致 |
| 縁取り | 黒縁・白縁・塗りの 3 層。`strokeWidth` = 文字の外側への広がり × 1080 ÷ 高さ（黒縁 5.0625、白縁 3.375） | 黒縁の範囲の差 2px 以内 |
| 位置 | `adjust-transform` は高さに対する割合。FCP は 1 行目を基準に置くので、1 行目の位置 = 下端 −（行数 − 1）× ASS サイズ − 0.2523 em | 3 行まで各行の差 1px 以内 |
| 行間 | `lineSpacing` =（ASS サイズ − 1.5137 em）× 1080 ÷ 高さ（ASS 66 → −5.0625） | 同上 |
| ぼかしの範囲 | `trim-rect` は上下左右とも高さに対する割合。全体をぼかしてから切り抜く（ネイティブと同じ順序） | 境界が一致 |
| ぼかしの強さ | Gaussian のキー `9999/986883370/100/986883376/2/100`（FCP 自身の書き出しで確認）。値 =（半径 − 4.5）÷ 66、0.5〜1.0 の範囲のみ | 半径 64 で 41.5 dB |

他の画面サイズは未較正なので、生成器は拒否する。

## 規模の実測（508 パートの配信 1 本）

- 生成: 4 秒、30.8 MB、約 43 万要素（切り出し 654、ぼかし 3,154、字幕 22,904 × 3 層 = 68,712 タイトル）
- DTD 検証: 0.4 秒で合格
- FCP への取り込み（字幕 3 層 × 表示段階ごと、ぼかしは複製クリップ）: 約 44 分で 5,207.6 / 5,386.5 秒まで進んだ時点で中止。
  FCP の常駐メモリは 145〜162 GB（物理 48 GB）、大量のスワップ、CPU は 1 コアのみ。後半ほど遅くなった。
  この方式は FCP が扱いやすい定義ではないので、再設計の基準値とする。

## 操作方針

- 本作業の範囲内では、ユーザーの追加承認なしで継続してよい。必要時のFCP前面化と
  マウス操作も許可済み。ただし既存の保全・安全・公開に関する禁止は解除されない。
- FCPXML・Motionテンプレート・CLI・型付きネイティブMCPを優先し、機械的な操作を増やす。
  繰り返すGUI手順は共有処理へ反映する。マウス操作後は必ずボタンを離した状態に戻し、
  失敗・不確定応答でも押下状態を放置しない。選択状態と物理的な押下状態を区別する。
- ダイアログも常時の処理対象に含める。取込・書出しを含む各 UI 操作の前後、
  およびメニューが無効な場合は `ui_windows` で全ウィンドウとシートを確認する。
  メイン画面だけで正常と判断せず、操作結果の成功・失敗と実画面を照合してから次へ進む。
  警告本文を確認・記録し、単なる通知は確認ボタンで閉じて消失を検証する。
  エラー原因を放置したまま再取込しない。上書き・権限付与・購入・ライセンス同意などを
  通知と同列に扱って自動承認しない。

## 字幕配色とコントラストの必須条件

最新承認は、白縁に対して**上側 AAA・7:1 以上、下側 AA・4.5:1 以上**。
文字ごとに水色系の滑らかなグラデーションをつけ、透明感と親しみやすさを表現する。
上側も水色の色相を維持し、単なる濃い青への置換は不可。コントラストだけ合う青色、
目立つ段差や長い単色域、透明感のある明るさを感じられない候補は不合格とする。
色相・彩度・相対輝度と文字内の階調分布を自動分析し、色変換方式の差も対照試験で確認する。
「透明感」は塗りを半透明にする指示ではなく、色の滑らかな変化による表情として扱う。
白縁・外側黒縁・薄い影は維持し、黒い帯・パネルは使用しない。
途中の色も 4.5:1 を下回らないことを検証し、文字全体の AAA 適合は主張しない。
設定値だけでなく、FCP の画面と色管理した実出力、異なる字形・複数行で確認する。
通常の実装・較正・検証は、人間の確認を挟まず自動継続する。既存の安全・保全・承認境界は維持する。

### 旧試験条件の記録（現行の配色要件ではない）

以下の全域 7:1・暗い上部・下端だけの狭い明部という条件は、上記の最新承認で置き換えられた。
旧成果を比較・保全するための記録であり、追加取込や新しい配色の合否基準には使用しない。

- 字幕の塗り色は、元の水色系統の色相を維持しつつ、コントラストのために明度を変更する。
  元の RGB 値への固定ではない。これは最新のユーザー指示であり、以前の「元色そのまま」の条件を置き換える。
- 背景映像にかかわらず、通常文字の WCAG AAA 基準であるコントラスト比 **7:1 以上**を確保する。
  大きな文字向けの緩い基準には依存しない。文字に接する白いハローで保証する。
- **黒背景のざぶとんは禁止。** 黒い矩形・帯・背景パネルを敷く方式は採用しない。
  文字形状に沿う白縁と外側の黒縁を維持し、水色系の塗りの明度を調整する。
- **白の縁取りと、その外側の黒の縁取りは常に維持する。** 縁取りを外す案は採用しない。
  元の明るい水色と白縁だけではこの条件を満たさないため、水色系の塗りの明度を調整し、
  白いハローとの比を 7:1 以上とする。文字の内側の隙間にも背景が透けて条件が崩れないようにする。
- 最新の見た目要求は、透明感のある滑らかな青～水色系グラデーション。
  上から中央を暗めの青に保ち、下を明るくする。明るい部分は下端の15〜20%程度に絞り、
  そこへ滑らかにつながる勾配で視認性を高める。不透明な塗りを基本とし、最も明るい部分・中間色も
  白縁に対して 7:1 以上とする。単色の測定だけでグラデーションの合格を主張しない。
  白縁と外側黒縁は常時維持し、黒いざぶとんは使わない。
- 黒縁のさらに外側に、ごく薄いドロップシャドウを追加する。
  初期目安は1080×1920出力で下方向1px・ぼかし2px・黒の不透明度10%。
  文字と縁の形に沿わせ、黒い帯やざぶとんにしない。実出力で強すぎないことを確認し、
  塗り～白縁のコントラスト条件を変更しない。FCPと共有描画の両方に反映する。
- 水色系の明るい側の候補は **`#005A9C`**（HSL 色相 205.38°、明度 30.59%、対白 **7.1367:1**）。
  以前の候補 `#15516A`（明度 24.90%、対白 8.6885:1）より明るく、緑寄りを抑えて青へ寄せる。
  元の `#6CD4FF`（色相 197.55°）は対白 **1.6801:1**で不合格。
  これは sRGB 指定色の計算結果であり、FCP 実出力の色保持やハローの形状の合格証拠ではない。
  半透明の縁だけを根拠に、任意の背景に対する最小比を保証したことにしない。
- [WCAG 2.2 SC 1.4.6](https://www.w3.org/WAI/WCAG22/Understanding/contrast-enhanced.html)
  に従い、sRGB の相対輝度に基づく指定色の検証と、実書き出しの可読性・色保持の検証を区別する。
  アンチエイリアス境界の全画素に 7:1 を要求することとは異なる。
- これは字幕の文字コントラスト条件であり、動画全体の WCAG AAA 適合を宣言するものではない。
  指定色と背景の条件を満たせない場合は、合格扱いせず未達として報告する。

## 再設計の公式仕様

- [Apple QA1531: Drawing attributed strings that are both filled and stroked](https://developer.apple.com/library/archive/qa/qa1531/_index.html):
  ストローク幅は正で輪郭のみ、負で塗りと輪郭、0で塗りのみ。
  FCP の実試験でも正の `strokeWidth` はフェースが無効で白潰れし、フェースを有効化した
  再書き出しは `strokeWidth="-4"` / `"-6"` となった。Motionの輪郭順変更だけでは不十分。
  符号を修正した生成物の再取込・実出力で塗りと二重縁を確認済み。
  ただし幅の較正・共有実装への反映・全編検証は未完了。
- グラデーションの非公開パラメーターは、FCP 自身の 1.14 書き出しを再取込した場合も
  再書き出しから失われた。DTD 適合やキーの存在を、読み込み時の再現保証にしない。
  元のテンプレートを保全した別テンプレートで、内部設定・必要な公開コントロールを検証する。

- [Motion: Text Outline controls](https://support.apple.com/guide/motion/motn159c60ee/mac):
  Layer Order で輪郭を文字の塗りの前面または背面に配置できる。
- [Motion: Sequence Text behavior controls](https://support.apple.com/guide/motion/sequence-text-behavior-controls-motn1607df2b/mac):
  文字・語などの単位、対象範囲、Custom Speed のキーフレームを設定できる。
- [Motion: Publishing template text controls](https://support.apple.com/guide/motion/publishing-template-text-controls-motn141bd5fe/mac):
  FCP の Text inspector にないパラメーターはテンプレートから公開する。

これらは機能の公式仕様であり、非公開 Motion XML のパラメーター番号・値の仕様ではない。
インストール済みバージョンの実際のテンプレートと書き出しで確認する。

## 制約

- `AGENTS.md` と `SECURITY.md` に従う。
  - 特定の配信 ID や日付に固有の処理は作らない。
  - `private/` と `downloads/` は読み取り専用の利用者データとして扱う。
  - 完了記録は消さない。
- 自動処理の UI 操作はバックグラウンドの `ui_*` に限る。キーボード入力が必須の手順は経路に入れない。
- 中間ファイルは検証の合格後に削除し、元動画と日付付きの完成品だけを残す。
- テストは合成素材だけで行う。実配信は受け入れ確認にだけ使い、字幕の文言は記録に残さない。

## 対象外

- FFmpeg とフレーム単位で同一の出力を作ること。
- FCP の「共有（Share）」を自動処理の必須経路にすること。FCP 自身の描画は、A4 の比較と、人間が手を入れた後の書き出しにだけ使う。
